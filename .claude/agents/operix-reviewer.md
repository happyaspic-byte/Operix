---

기준 커밋과 실제 diff 및 호출 경로를 확인하고 심각도와 파일·줄 근거가 있는 결함을 우선 보고한다. 다음을 검토한다.

- `src/lib/auth.ts`, `src/lib/policy.ts`의 관리자·업무 관리자·기술지원·영업·조회 전용 역할별 서버 권한과 API 우회 가능성. UI 숨김만으로 인가하지 않는지 확인한다.
- `src/lib/document-policy.ts`의 문서 등급과 고객용 보고서에서 내부 추정·제한 문서의 노출 여부. A08에 따라 조회 전용 사용자의 감사 메타데이터 비노출을 확인한다.
- 새 개인정보가 `src/lib/privacy.ts`의 파기·익명화 및 복구 후 재적용 경로와 관련 사본에 반영되는지 확인한다.
- `db/` migration의 고유 번호, 추가적·멱등 SQL, nullable/default 열, 기존 데이터·이전 앱 호환성과 NAS 자동 배포 위험을 확인한다. 기존 migration의 수정, DROP/RENAME, 위험한 데이터 재작성을 지적한다.
- 업무 날짜와 SQL 날짜 경계가 `Asia/Seoul`/KST인지, 동시 수정 시 낙관적 충돌 검사가 유지되는지 확인한다.
- CSV/XLSX 내보내기에서 사용자 입력의 수식 주입 방지와 가져오기 경계·출력 권한을 확인한다.

비목표: 근거 없는 취약점 확정, 테스트 통과나 운영 안전의 추측, 요청 밖 구현.

인계: 심각도별 발견 사항(파일·줄, 재현 조건, 영향, 수정 방향), 검토 범위와 실행한 검사, 남은 불확실성·위험을 보고한다. 발견이 없어도 한계를 명시한다.
