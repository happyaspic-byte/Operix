# 운영 보강 및 배포 검증

2026-09-21 변경 기준: 개인정보 파기 후 쓰기 차단, 사업장 고객사 변경 무결성, 계약·작업 자산 검색, 쓰기 잠금 제한, Node 24 일치, 백업 실행 안전성 및 배포 버전 확인.

## 실행 중인 버전 확인

이미지에 빌드한 커밋 SHA가 포함됩니다. 공개 `/api/health`는 상태와 SHA만 반환하고, 백업·디스크·DB 상세 정보는 관리자 설정에서 확인합니다.

```sh
node scripts/verify-deployment.mjs https://실제-서비스-주소 40자리_배포_커밋_SHA
```

이 명령은 HTTPS 인증서, 리다이렉트 없는 정상 health 응답, 정확한 버전, 로그인 페이지를 읽기 전용으로 검사합니다. 로그인 성공이나 실제 데이터 처리, NAS 저장소 복구까지 검증했다는 의미는 아닙니다. HTTP 허용 옵션은 격리된 CI 컨테이너 검사에만 사용합니다.

검증 단계는 PR CI → main CI → 테스트한 이미지 게시 → NAS 적용 → 실제 HTTPS 서비스 확인입니다. GitHub Actions 성공이나 `nas-deploy` 갱신만으로 NAS 배포 완료를 판정하지 않습니다. 해당 실행의 `operix-verification` 아티팩트에는 커밋/실행 번호, 도메인 테스트 출력, 브라우저 결과, PostgreSQL 1,000행 import 측정 결과가 포함됩니다.

## 백업과 복구

NAS 자동 배포의 PostgreSQL 사전 덤프(최근 7개)는 같은 NAS의 배포 복구 보조 자료입니다. 암호화된 DB·첨부·설정 전체 백업 및 외부 복사와 구분합니다.

- `backup.sh`와 `restore.sh`는 `flock`으로 동시 실행을 차단합니다. 동일 배포에는 반드시 동일 호스트 체크아웃을 사용합니다. 잠금 파일은 삭제하지 않습니다. 여러 NAS/체크아웃 사이의 분산 잠금을 제공하지 않습니다.
- 백업 실패 시에도 원래 실행 중이던 web/worker만 재개합니다. 복구 실패 시 쓰기 서비스는 중지 상태로 남아 원인 확인을 기다립니다.
- `scheduled-backup.sh`는 매번 독립 디렉터리를 만들고, rsync가 성공한 뒤에만 DB에 외부 복사 완료를 기록합니다. 외부 전송 실패는 로컬 백업 완료와 별도로 판정합니다.
- 상태 감시는 암호화된 백업만 인정합니다. 외부 복사 시각뿐 아니라 백업 원본 생성 시각도 유효해야 합니다. 오래된 백업을 다시 복사해도 정상으로 판정하지 않습니다.
- 실제 스케줄·접근 제한·암호화 키 보관·외부 복사·격리된 복원 시험이 확인된 뒤 `BACKUP_REQUIRED=1`, `BACKUP_REMOTE_REQUIRED=1`을 적용합니다. 최대 허용 시간은 `BACKUP_MAX_AGE_HOURS`(기본 26시간)입니다. 이번 변경은 기존 배포의 감시 설정을 임의 활성화하지 않습니다.
- rsync 성공은 원격 전송 성공 증거입니다. 별도 호스트에서의 복원 성공은 정기 복원 훈련으로 확인하고 기록해야 합니다.

## 런타임과 동시 작업

Node 24를 설치와 시작 단계에서 검사하며 Docker와 타입 정의도 같은 메이저 버전을 사용합니다. Dependabot의 Node 이미지/타입 메이저 자동 변경은 별도 런타임 업그레이드 작업으로 다룹니다.

업무 쓰기는 기존 직렬화 순서를 유지합니다. 잠금 대기는 최대 5초이며, 경합 시 HTTP 503과 `Retry-After: 5`로 재시도를 안내합니다. 실패한 트랜잭션은 전체 롤백됩니다. UI가 자동으로 쓰기를 재전송하지 않으므로 사용자는 저장 결과를 확인하고 재시도합니다. PostgreSQL 테스트는 잠금 중 읽기, 실패 시 원자성, 1,000행 import의 실제 시간을 측정합니다. 이 측정은 CI 환경의 결과이며 운영 처리량 보증이 아닙니다.

## main 보호 설정

관리자 설정 권한으로 main에 PR 필수, 최신 기준 필수 검사 `application` / `container`, 강제 push 금지, 삭제 금지를 적용합니다. CI 발행 경로인 `nas-deploy`에 같은 규칙을 무조건 적용하면 배포 게시가 막힐 수 있으므로 main에만 적용합니다. 1인 운영 환경의 필수 승인 인원은 운영자 가용성에 맞춥니다.

현재 GitHub 플러그인의 제공 기능에는 보호 규칙 변경 API가 없어 코드 수정과 별도로 인증된 저장소 설정에서 적용·확인이 필요합니다. 적용 사실을 확인하기 전까지 보호 설정 완료로 기록하지 않습니다.

## 배포 전 확인할 운영 정보

실제 HTTPS 주소, NAS/Portainer 배포 결과, 최근 암호화 백업 및 외부 복원 증거가 필요합니다. 제공되지 않은 값은 추측하지 않습니다. 파기·장애 주입·복원 테스트는 합성 데이터와 격리 환경에서만 수행합니다. 운영에서 데이터 파기나 자동 복원으로 배포를 검증하지 않습니다.
