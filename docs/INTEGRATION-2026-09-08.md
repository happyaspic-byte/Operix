## 유지한 계약과 추가 변경

- 실행 환경은 Node.js `>=24.0.0 <25`다. 9월 6일 프롬프트·조사에 남은 Node 22 안내를 현재 요구 사항으로 사용하지 않는다.
- 페이지 수치는 최신 main의 엄격한 양의 정수 문자열 계약을 유지한다. `page`는 1~100000, `limit`는 1~100이며 생략한 경우 기본값을 사용한다. 공백·소수·부호·선행 0·범위 초과 입력은 400으로 거부한다. 구버전의 자동 보정 동작으로 되돌리지 않는다.
- JSON 본문은 UTF-8 바이트 기준 1,048,576바이트까지이며 초과 시 413이다. 최신 main의 스트림 바이트 검사, 기본 15초 수신 제한과 408, 올바른 UTF-8·JSON 객체 검사는 유지한다. 이번 보안 통합에서는 수신 취소 실패가 초과 응답을 가리지 않도록 보완하고 경계·미저장 회귀를 추가했다. 이는 프로세스 전체 메모리 상한을 보장한다는 의미가 아니다.
- multipart도 최신 main의 공통 스트림 검사와 기본 21 MiB 본문 상한을 유지한다. 이 값은 개별 파일 크기 상한과 다르며, 과거 보안 worktree의 제한된 조사 범위를 현재 multipart에 제한이 없다는 뜻으로 해석하지 않는다.
- `0000-MM-DD`는 저장 전 날짜 검사와 조회 필터에서 거부한다. 날짜 형식 오류가 DB 형 변환까지 도달하지 않도록 공통 유효성 검사를 사용한다.
- 새 DB 회귀 검증은 PostgreSQL에서 전용 스키마를 만들고 정리한다. 기존 도메인 검증의 스키마와 분리해 비멱등 마이그레이션의 중복 실행을 피한다.

## UI 통합 동작

아래는 병합한 구현 내용이며 브라우저 실행 결과는 다음 표에서 별도로 기록한다.

- 검색·상태·내 담당·기간·만료 조건을 함께 초기화하고 첫 페이지로 돌아간다. 검색 결과 없음, 미등록, 조회 중, 조회 실패를 구분한다. 페이지 조회 중에는 하단 페이지 이동 영역과 키보드 포커스를 유지하고 중복 이동을 막는다.
- 표 가로 스크롤 영역을 키보드로 접근할 수 있고 모달을 닫으면 열었던 버튼으로 포커스가 돌아간다. 입력 오류를 해당 필드와 연결하며 모바일 메뉴는 포커스 이동과 Escape 닫기를 처리한다.
- 편집 중 입력 취소 확인을 유지한다. 저장 시 409 충돌이 발생하면 현재 입력을 보존한 채 서버 값을 비교하고, 사용자가 선택한 값으로 최신 버전에 다시 저장할 수 있다.
- 가져오기 제목·템플릿·요청은 선택한 자료 종류를 따른다. 처리 중에는 닫기, 파일 선택과 매핑 변경을 막는다. 확장된 관계 검색·가져오기와 기존 업무 기능을 유지한다.

단위·DB 검증은 보안·버그 통합 후 실행했으며 이후 해당 앱 로직·단위 테스트는 바뀌지 않았다. 전체 E2E는 UI 통합과 테스트 수정까지 포함한 별도 실행이다. `test-results/`는 Git에서 제외된 로컬 실행 산출물 경로이며 원격 CI는 실행별 아티팩트로 결과와 UI 증거를 보관한다.

첫 전체 E2E는 31개 통과·선택자 관련 2개 실패였다. `a696ea7`에서 실제 접근 가능한 컨트롤 이름에 선택자를 맞추고 해당 2개 검증을 통과한 뒤, 앱 DB를 새로 준비해 전체 33개를 재실행했다. 이 과정에서 앱 코드는 수정하지 않았다. 최종 실행은 `E2E_START_SERVER=1 npm run test:e2e -- --output=test-results/integration-e2e-final --trace=off --retries=0`이며 전용 환경의 `APP_URL`·`PORT`와 가상 자료를 사용했다.

첫 원격 검증([aafedd0 실행](https://github.com/happyaspic-byte/Operix/actions/runs/34211661306))은 PostgreSQL 110개와 container 작업이 통과했지만, E2E에서 페이지 전환용 로딩 표시와 목록 로딩 표시가 동시에 매칭되어 32개 통과·1개 실패로 종료됐다. 해당 선택자를 `.list-panel` 안으로 한정하고 같은 시나리오를 로컬에서 재시도 없이 3회 연속 통과했다. 대기·빈 목록·조회 실패의 검증 조건과 앱 구현은 유지했다. 후속 커밋의 전체 원격 결과는 위 GitHub Actions 링크에서 확인한다.

9월 5일의 Docker·ClamAV·암호화 백업/복구·CI 결과는 [기존 검증 기록](VERIFICATION.md)의 해당 코드 기준에 속한다. 이번 로컬 실행은 PostgreSQL 앱 검증이며 배포 컨테이너·실제 ClamAV·암호화 복구의 재검증 결과를 포함하지 않는다. 원격 CI의 해당 검사 결과는 대상 커밋의 실행에서 확인한다. 기존 검증 문서의 화면 이미지는 9월 5일 기록으로 유지한다.

UI의 720×500 viewport와 deviceScaleFactor 2 검사는 200% 확대에 대응하는 reflow 모사다. 실제 브라우저 메뉴 확대·전체 WCAG·화면낭독기 검증을 대신하지 않는다.
