# 점검 대상 자산 여러 개 선택

점검 등록 또는 수정 화면에서 **대상 자산**을 검색하고 체크하세요. 같은 고객의 자산을 1개부터 200개까지 한 점검에 연결할 수 있습니다. 검색어를 바꾸어도 이미 선택한 자산은 유지되며, 선택 목록에서 해제할 수 있습니다. 자산 상세 화면에서 점검을 등록하면 해당 자산이 먼저 선택됩니다.

여러 장비를 한 번에 방문하는 경우 하나의 점검으로 관리할 수 있습니다. 예정일·담당자·진행 상태·체크리스트·결과는 점검 전체가 공유합니다. 장비별로 독립된 일정이나 결과가 필요하면 점검을 따로 등록하세요.

대상 전체의 이름과 자산번호는 점검 목록·상세, 내보내기 및 새로 확정하는 보고서에 반영됩니다. 대시보드와 달력에서는 하나의 방문 점검으로 표시됩니다. 각 대상 자산의 상세에서도 해당 점검을 찾을 수 있습니다. 후속 점검을 만들면 대상 목록을 이어받습니다. 이미 확정한 보고서는 확정 당시의 내용을 보존합니다.

## 기존 기록과 반복 점검

기존 점검의 대상 자산은 그대로 유지됩니다. 후속 조치 등 자유 입력 문구에 적힌 장비를 자동으로 추가하지 않으므로, 기존 방문 점검에 대상을 추가하려면 수정 화면에서 선택해 저장하세요. 한 점검의 고객을 다른 고객으로 바꿀 수는 없습니다.

반복 점검 계획은 기존처럼 기준 자산 한 개를 사용합니다. 생성된 개별 회차에는 같은 고객의 자산을 추가할 수 있으며 원래 기준 자산은 유지해야 합니다. 개별 회차에서 추가한 대상이 이후 회차의 반복 계획에 자동 반영되지는 않습니다.

기존 보관 정책에 따라 대상 자산이나 그 사업장·고객을 보관하면 아직 예정 상태인 점검은 취소됩니다. 여러 대상 중 하나를 보관해도 해당 방문 점검 전체에 적용됩니다. 진행 중이거나 완료된 점검의 이력과 자산 연결은 보존합니다.

## API 및 배포

- 점검 생성·수정의 `asset_ids` 배열이 대상 전체를 지정합니다. 대표 연결인 기존 `asset_id`도 호환성을 위해 유지합니다. 두 필드를 함께 보내면 `asset_id`는 배열의 첫 번째 대상이어야 합니다.
- 기존 클라이언트가 수정 요청에 `asset_id`만 보내면 다른 대상 연결을 보존합니다. 수정에는 기존 버전 충돌 검사와 권한 검사가 적용됩니다.
- `db/004_inspection_assets.sql`은 대상 연결 테이블과 인덱스를 추가하고 기존 점검의 대표 자산을 연결합니다. 새 환경변수는 없습니다.
- DB 백업에는 대상 연결도 포함됩니다. 복구 검증은 연결 개수뿐 아니라 점검·자산 ID 쌍의 일치와 보고서 스냅샷 보존을 확인합니다.
