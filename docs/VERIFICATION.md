# Operix v0.1 검증 기록

평가 범위는 고객·설치 자산·계약·점검·장애·확정 보고서를 연결하는 사내 운영 MVP다. 회계·구매·재고·인사까지 포함하는 전사 ERP 완성도를 의미하지 않는다. 모든 검증 자료는 가상 데이터다.

## 검증 현황

- TypeScript 검사와 Next.js 운영 빌드 성공.
- Node 데이터·권한 테스트 28개 통과. 날짜 필드는 그대로 보존하고 시각은 한국시간으로 표시하는 경계 검증 포함.
- Chromium 업무·API 시나리오 11개 통과. 데스크톱과 모바일 화면을 직접 캡처했다.
- 주요 화면 5곳에서 axe의 serious·critical 위반 0건. WCAG 전체 준수 인증은 아니다.
- 운영 의존성 검사: 알려진 취약점 0건(`npm audit --omit=dev`).
- PostgreSQL 17, 백업 복구, Docker 검증은 GitHub Actions 첫 실행 후 이 문서에 결과를 기록한다.

## 확인한 업무와 방어 동작

고객 → 사업장 → 자산 → 계약 연결 → 점검 완료 → 보고서 확정을 브라우저와 API로 수행했다. 확정 후 원본 점검 내용을 변경해도 기존 보고서 내용이 유지된다. 인쇄용 PDF를 생성했다.

날짜·만료·월말 반복 일정, 일정·알림 중복 방지, 다른 고객사 자산 연결 거부, 중복 자산 ID, 트랜잭션 롤백, 오래된 수정 버전 거부를 검사했다. XLSX 한글 왕복, CSV 수식 주입 처리, 가져오기 중복 확정 거부, 업로드 원본 바이트와 비로그인 다운로드 차단을 검사했다.

역할별 서버 권한과 민감 필드 제거, 비로그인 요청·다른 출처 변경 요청 차단, 로그인 실패 제한, 사용자 정지 및 로그아웃 후 세션 회수를 검사했다. 이 검사는 침투 테스트나 외부 보안 감사를 대신하지 않는다.

## 평가 방식과 남은 범위

자체 평가는 업무 기능 30점, 데이터 정합성 20점, 보안 20점, 사용성 15점, 운영 준비 15점의 총 100점으로 산정한다. GitHub 검증 결과를 확인한 뒤 근거와 감점 사유를 기재한다. 외부 인증 또는 타 ERP와의 동등 조건 성능 순위가 아니다.

실제 사내 Ubuntu 서버의 설치·접속, DNS·HTTPS·VPN·백업 대상, 실자료 이관, 현장 사용자 인수 시험, 운영 부하·장애 복구 시간은 아직 검증하지 않았다. SSO/MFA, 외부 메일 알림, 악성코드 검사 연동, 회계·재고·인사는 후속 범위다.
